#### 2) 주요 시행착오 및 해결 과정

##### 2.1 PowerShell 파싱 오류 연쇄 (가장 큰 장애)
**문제**: 
- 원라이너 PowerShell 명령어에서 변수 참조 오류 (`$pt` → `${pt}` 필요)
- 한 줄 if문 파싱 실패로 블록 if 강제 사용
- 파일 핸들 충돌 (`server_stdout.log` 잠금)

**해결**:
- `ops/win/00_fix_env.ps1`: 포트 정리 로직을 블록 if로 수정, 변수 참조 `${pt}` 적용
- `ops/win/01_run_server.ps1`: 파일 핸들 충돌 제거, 단순 실행으로 변경
- 환경변수 전파를 동일 세션에서 보장

##### 2.2 포트 바인딩 혼선 (8000 vs 8080)
**문제**:
- 서버가 계속 8000에 바인딩되어 AC 측정 불가
- 환경변수 PORT=8080이 새 세션에서 전파되지 않음

**해결**:
- `00_fix_env.ps1`에서 PORT=8080 강제 설정
- `01_run_server.ps1`에서 동일 세션 실행으로 환경변수 보장
- netstat으로 8080 바인딩 확인: `TCP 0.0.0.0:8080 LISTENING 32048`

##### 2.3 /healthz 성능 이슈 (2.3~2.5s → 9~18ms)
**문제**:
- 초기 측정값이 AC 기준(500ms) 대비 5배 초과
- debug=True, use_reloader=True로 인한 오버헤드

**해결**:
- `webhook_server.py` 수정: `debug=False, use_reloader=False, threaded=True`
- 측정 대상을 127.0.0.1:8080으로 고정
- 최종 측정값: t0=24ms, t1=9ms, t2=18ms (AC 충족)

##### 2.4 SIGTERM 측정 실패
**문제**:
- PowerShell 파싱 오류로 정확한 종료 시간 측정 불가
- `$duration = ($end - $start).TotalMilliseconds` 구문 오류

**해결**:
- 기능적 graceful shutdown은 확인 (유휴/요청 중 모두 정상 종료)
- 측정값은 수기 기록으로 대체

#### 5) 재발 방지 대책

##### 5.1 PowerShell 스크립트 표준화
- **원칙**: 한 줄 if문 금지, 블록 if만 사용
- **변수 참조**: `$var` → `${var}` (특수문자 포함 시)
- **파일 핸들**: 동시 접근 시 충돌 방지를 위한 단일 세션 실행

##### 5.2 포트 관리 표준화
- **기본 포트**: 8080 고정 (8000 사용 금지)
- **환경변수**: 동일 세션에서 설정 후 서버 실행
- **검증**: netstat으로 바인딩 확인 필수

##### 5.3 성능 측정 표준화
- **측정 대상**: 127.0.0.1:8080 고정 (DNS 지연 회피)
- **런타임**: debug=False, use_reloader=False, threaded=True
- **웜업**: /health 1회 선호출 후 /healthz 측정

##### 5.4 스크립트 실행 순서 표준화
1. `00_fix_env.ps1` (환경 준비)
2. `01_run_server.ps1` (서버 기동)
3. `02_check_health.ps1` (헬스 체크)
4. `03_sigterm_idle.ps1` (유휴 종료)
5. `04_sigterm_inflight.ps1` (요청 중 종료)
6. `05_invalid_sig.ps1` (보안 로그)
