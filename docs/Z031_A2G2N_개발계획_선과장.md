### 지시문: A2G2N V1.0 추진을 위한 개발 지시(수신: 서대리)

- 목적: A2G2N 파이프라인의 Stage 1(AI2G) 구현 및 G2N 연동 안정화
- 기간: D+0~D+14, M1 완료 기준
- 보고: 매일 18:00 전일 로그와 리스크 요약, 마일스톤 완료 시 즉시 보고

1) Stage 1 리서치 Agent PoC 구현

- 명령 입력을 받아 웹 리서치 수행
- 결과물 생성 규격
    - 산출: PDF 또는 MD, 필수 메타데이터(JSON sidecar)
    - 메타데이터 필드: title, url, source_domain, published_at, collected_at, content_hash, topics, project_hint
- 저장 경로
    - Google Drive /INBOX/AI2G/<프로젝트>/ 날짜_제목_해시.pdf
    - 동일 경로에 meta.json 동명 파일 저장
- 제약 준수
    - 로봇, 저작권, 약관 준수. 전문 저장 불가 시 링크·요약만 저장

2) G2N 연동 이벤트 발행

- 파일 저장 직후 Drive 변경 이벤트 발행
    - payload: drive_path, file_id, file_url, meta_json_url, project_hint
- 기존 G2N 라우팅과 호환
    - INBOX 3폴더 체계 준수
    - 라우팅 실패 시 재시도 최대 3회, 백오프 5s/15s/45s

3) Notion 등록 품질 보장

- 생성 대상 DB: 프로젝트리소스 DB 또는 개발문서 DB, 라우팅 규칙 준수
- 최초 속성 세팅
    - 문서 제목: 원제목 앞에 접두 “A2G”
    - 링크: 원문 URL
    - Google Drive URL: 파일 URL
    - 수집 경로: AI2G
    - 리소스 타입: 규칙 기반(뉴스·법규·리서치)
    - 작성일: collected_at
    - 상태: 초안
- 중복 방지: content_hash 기준 idempotency

4) 명령 채널 PoC

- 1안: Notion 명령 페이지에서 “/명령 생성” 버튼 → Cloud Function 호출
- 2안: Slack Slash Command “/a2g topic:… project:…”
- 둘 중 1안을 우선 구현, 2안은 선택 구현

5) 로깅·모니터링

- 필수 로그 필드: trace_id, step, duration_ms, status, err_code, err_msg
- 대시보드 지표
    - 수집 성공률, 평균 수집 소요, 라우팅 정확도, 재시도율
- 장애 기준
    - 5xx 3회 연속 또는 성공률 < 90% 1일: 즉시 알림 및 원인분류 보고

6) 보안·시크릿

- 모든 키는 환경변수 혹은 비밀저장소에서 주입
- Notion API 키 최신값 적용 후 커밋 금지
- 드라이브 서비스 계정 키는 로컬/CI에 평문 저장 금지

7) 테스트 계획(M1)

- 조대표 지정 주제 2개 × 각 5건 = 10건 수집
- 합격 기준
    - 라우팅 정확도 ≥ 90%
    - Notion 속성 누락 0건
    - 중복 생성 0건
    - 평균 처리 시간 ≤ 3분/건(수집→노션 등록)

8) 산출물

- 소스 저장소 브랜치와 README(실행 방법·시크릿 주입)
- API 스펙 문서(명령 파라미터, 응답, 에러코드)
- PoC 결과 보고서(10건 표, 실패 원인·개선안)
- 운영 체크리스트(배포, 키 교체, 롤백)

9) 일정

- D+0~D+2: 명령 채널 1안, 수집기 골격, Drive 저장 및 메타 생성
- D+3~D+5: G2N 이벤트 연동, Notion 등록 속성 매핑
- D+6~D+8: 예외·재시도, 중복 방지, 로깅·대시보드
- D+9~D+10: 10건 드라이런, 리포트
- D+11~D+14: 개선 반영 및 M1 종료
