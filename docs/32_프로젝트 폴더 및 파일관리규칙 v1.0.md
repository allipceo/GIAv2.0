I. 목적 및 필요성
GIA 프로젝트의 규모가 커지고 다양한 기업(효성, 두산, 한진 등)을 대상으로 하는 프로젝트가 진행됨에 따라, 일관되고 체계적인 폴더 및 파일 관리 규칙을 수립하는 것이 필수적입니다. 본 문서는 모든 팀원(AI 에이전트 포함)이 지켜야 할 표준을 정의하여, 코드의 재사용성을 높이고, 파일 관리의 혼란을 방지하며, 프로젝트의 안정적인 확장을 보장하는 것을 목표로 합니다.

II. GIAv2.0 표준 폴더 구조
향후 모든 브랜치와 프로젝트에 적용될 표준 폴더 구조는 다음과 같습니다. 각 폴더의 용도를 명확히 구분하여 불필요한 파일의 혼재를 방지합니다.

GIAv2.0/
├── projects/                      # 프로젝트별 파일 저장소 (핵심 폴더)
│   ├── [프로젝트명]_project/
│   │   ├── code/                  # 프로젝트별 스크립트 (예: hyosung_news_collector.py)
│   │   ├── data/                  # 프로젝트별 데이터 (예: hyosung_news_data.json)
│   │   └── docs/                  # 프로젝트별 문서 (예: 효성중공업 심층 조사 보고서)
│   └── [다음 프로젝트명]_project/
├── code/                          # 모든 프로젝트에서 공통으로 사용되는 범용 스크립트
│   ├── notion_db_manager.py       # 노션 DB 관리 범용 스크립트
│   ├── webhook_trigger_server.py  # 자동화 트리거용 웹훅 서버
│   └── ...
├── docs/                          # 프로젝트 전체에 적용되는 공통 문서
│   ├── GIAv2.0_협업헌장_V3.1.md    # 협업 지침
│   ├── GIA_기본계획_V1.4.docx     # 프로젝트 기본 계획
│   └── ...
├── data/                          # 모든 프로젝트에서 공통으로 사용되는 데이터
│   ├── news_data.json             # 범용 뉴스 데이터
│   └── ...
├── src/                           # 소스 코드 (유틸리티 등)
│   └── utils/
│       └── file_helper.py         # 파일 경로 등 헬퍼 함수
└── etc/                           # 기타 자료

핵심 원칙: 특정 프로젝트에 종속된 파일은 반드시 projects/[프로젝트명]_project/ 폴더 내에 위치해야 합니다.

III. 파일 명명 규칙 및 관리 원칙
3.1. 문서 파일 명명 규칙
모든 문서 파일(특히 .md 형식)은 다음 규칙에 따라 명확하고 일관성 있게 작성해야 합니다.

규칙: [프로젝트명]_[기능/과업]_[버전]_[작성자]_[날짜].md

예시: doosan_risk_profile_analysis_v1.0_nabanjang_20250720.md

파일명 요소:

[프로젝트명]: hanjin, doosan, hyosung 등

[기능/과업]: plan, analysis, report, work_instruction 등

[버전]: v1.0, v1.1 등

[작성자]: nabanjang, seodaeri, noteamjang 등

[날짜]: YYYYMMDD 형식의 시간 스탬프

3.2. 코드 파일 명명 규칙
범용 스크립트: [기능]_ + [대상].py 형식으로 명명합니다.

예: google_news_collector.py, notion_db_manager.py

프로젝트별 스크립트: [프로젝트명]_ + [기능].py 형식으로 명명합니다.

예: hyosung_news_collector.py (-> projects/hyosung_project/code/ 폴더로 이동)

3.3. Notion DB를 통한 문서 아카이빙
docs/ 폴더는 임시 작업 공간 또는 공통 문서 저장소로 활용합니다.

최종적으로 확정된 모든 보고서 및 계획 문서는 노션의 **'GIA 문서 아카이브 DB'**에 체계적으로 저장하고 관리합니다.

Notion DB에 저장 시, 프로젝트명, 버전, 작성자, 생성일시, 파일 링크 등 메타데이터를 함께 기록하여 검색 및 관리를 용이하게 합니다.

IV. 책임 및 과업
서대리(Lead Developer):

본 지침에 따라 GIAv2.0 폴더 구조를 재정립하고, 모든 파일이 올바른 위치에 배치되도록 합니다.

향후 새로운 프로젝트 시작 시, projects/[프로젝트명]_project/ 폴더를 생성하고 해당 프로젝트의 파일을 관리합니다.

기존 스크립트가 새로운 파일 경로를 정상적으로 참조하도록 수정하는 작업을 담당합니다.

노션의 'GIA 문서 아카이브 DB'에 최종 문서를 업로드하는 스크립트를 구현합니다.

나실장(Project Manager):

모든 팀원이 이 지침을 준수하도록 감독하고, 필요한 경우 지침의 변경 및 업데이트를 주도합니다.

새로운 프로젝트 시작 전, 이 문서에 기반하여 서대리에게 폴더 구조 준비 및 스크립트 범용화 작업을 지시합니다.

모든 팀원(AI 에이전트 포함):

새로운 문서를 작성하거나 파일을 생성할 때, 본 규칙에 따라 파일명과 저장 경로를 결정하고, 협업 과정에서 이 지침을 철저히 준수합니다.

본 'GIA 프로젝트 폴더 및 파일 관리규칙'은 우리의 협업 생산성을 한 단계 끌어올리는 중요한 기반이 될 것입니다. 모든 팀원이 이 규칙을 준수하여 GIA 시스템의 무한한 확장 가능성을 함께 만들어가기를 바랍니다.
