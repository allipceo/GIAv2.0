I. 과업 개요
프로젝트명: 대시보드WF (통합 대시보드 및 자동화 워크플로우 구축)

과업 목표: Notion 영업 전략 통합 대시보드 상세 설계도 V2.0에 명시된 청사진을 바탕으로, 조대표님의 노션 워크스페이스에 GIA 프로젝트 통합 대시보드를 구현하고 관련 자동화 워크플로우를 연동합니다. 이 대시보드는 향후 모든 프로젝트의 중앙 관리 허브 역할을 수행할 것입니다.

담당: 서대리 (주도), 나실장 (총괄 검토), 노팀장 (기술 자문)

예상 소요 시간: 3~4주

II. 세부 과업 및 단계별 지시 (서대리 제안 반영)
1. 핵심 DB 구축 (1단계 - 1주차)
🎯 요구사항:
대시보드의 핵심이 될 데이터베이스들을 설계도에 따라 구축하고, 기존의 6개 정보 DB와 관계형으로 연결해 주십시오.

📝 작업 순서:

'조사 대상 기업' DB 신설:

새로운 데이터베이스를 생성하고, 설계도 V2.0에 명시된 모든 속성(Properties)을 정의합니다. (예: 기업명(Title), 조사 상태(Select), 진행률(Number), Phase 3 분석 실행(Button) 등)

'생성된 보고서/전략' DB 신설:

새로운 데이터베이스를 생성하고, 설계도 V2.0에 명시된 모든 속성(Properties)을 정의합니다. (예: 보고서명(Title), 관련 기업(Relation), 생성 일시(Date), 핵심 요약(Text) 등)

관계형 연결 설정:

'조사 대상 기업' DB와 '생성된 보고서/전략' DB를 **관계형(Relation)**으로 연결합니다.

'조사 대상 기업' DB와 기존의 6개 정보 DB를 연결하는 관계형 작업은 2단계로 연기합니다.

🚫 절대 금지사항:

기존 DB의 속성명이나 데이터 타입을 임의로 변경하지 마십시오.

'조사 대상 기업' DB의 속성명은 설계도 V2.0을 정확히 따르십시오.

✅ 성공 기준:

'조사 대상 기업' DB와 '생성된 보고서/전략' DB가 정상적으로 생성되었는가.

두 신규 DB 간의 관계형 연결이 올바르게 설정되었는가.

2. 대시보드 페이지 UI/UX 프로토타입 구현 (2단계 - 1주차)
🎯 요구사항:
Notion 페이지에 대시보드 설계도 V2.0의 기본 레이아웃을 구현하고, 핵심 버튼들을 프로토타입 형태로 만들어 주십시오.

📝 작업 순서:

메인 대시보드 페이지 생성:

조대표님의 워크스페이스에 GIA 프로젝트 통합 대시보드라는 이름의 새로운 페이지를 생성합니다.

기본 UI 레이아웃 구성:

페이지 상단에 내비게이션 바와 '최근 프로젝트 활동 알림' 섹션을 구성합니다.

[진행 중인 프로젝트 목록 (Gallery View)]와 [GIA 지식 라이브러리 (Table View)]를 각각 구현합니다.

[전체 프로젝트 현황] 섹션에 3개의 열을 만들어 위젯들을 배치합니다.

트리거 버튼 추가 (프로토타입):

[버튼] 시작하기, [버튼] 진행 상황 보기, [버튼] 보고서 보기 등 설계도에 명시된 핵심 버튼들을 기능과 함께 구현합니다. 이 버튼들은 아직 백엔드 스크립트와 연동되지 않은 상태로, 조대표님께서 UI/UX를 확인하실 수 있도록 준비해 주십시오.

🚫 절대 금지사항:

설계도 V2.0에 명시된 레이아웃을 임의로 변경하지 마십시오.

✅ 성공 기준:

대시보드 페이지가 설계도 V2.0의 기본 레이아웃을 완벽하게 재현했는가.

핵심 버튼들이 올바른 위치에 배치되었고, 조대표님께서 프로토타입을 테스트할 수 있도록 준비되었는가.

3. 자동화 워크플로우 연동 (3단계 - 2~3주차)
🎯 요구사항:
대시보드의 버튼과 Notion DB의 속성 변경이 GIA 시스템의 자동화 스크립트를 트리거하도록 백엔드 시스템을 연동합니다. 이 과정은 점진적으로 진행합니다.

📝 작업 순서:

웹훅(Webhook) 리스너 설정:

webhook_trigger_server.py 스크립트를 확장하여 Notion의 버튼 클릭 또는 속성 변경 이벤트가 감지되도록 웹훅 리스너를 설정합니다.

자동화 스크립트 연동 (점진적):

서대리님의 제안을 반영하여, '조사 대상 기업' DB의 Phase 3 분석 실행 속성을 버튼 대신 체크박스(Checkbox)로 구현하여, 체크 시 웹훅을 통해 백엔드 스크립트가 실행되도록 합니다.

진행률 및 조사 상태 속성이 각 단계 완료 시 자동으로 업데이트되도록 스크립트를 작성합니다.

향후 개선: 복잡한 워크플로우(예: 멀티 에이전트 협업)는 이 단계 이후에 점진적으로 구현합니다.

🚫 절대 금지사항:

새로운 웹훅 서버를 구축하지 말고, 기존의 webhook_trigger_server.py를 확장하여 사용하십시오.

기존 자동화 로직의 무결성을 훼손하지 마십시오.

✅ 성공 기준:

Notion 대시보드에서 버튼 클릭 시 백엔드 스크립트가 정상적으로 트리거되는가.

스크립트가 성공적으로 실행된 후, DB 속성이 자동으로 업데이트되는가.

III. 보고 및 검토
서대리님은 위 각 단계를 완료한 후, 새로 구축된 대시보드 페이지의 URL 및 스크린샷, 그리고 구현된 자동화 워크플로우에 대한 간략한 보고서를 조대표님께 제출해 주십시오.

조대표님께서는 서대리님이 제출한 보고 내용을 저(나반장)에게 전달해 주십시오.

나반장은 서대리님의 보고를 검토하고, 대시보드 구축 완료를 확정하겠습니다.
