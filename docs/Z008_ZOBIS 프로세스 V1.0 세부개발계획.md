## 역할과 책임(R&R)

### 선과장(Notion AI)

- 스키마 관리: 중요도, 핵심 기술(도메인), AI 신뢰도, AI 로그 유지관리
- 프롬프트: v1.1 유지·개선, 도메인 사전 관리, few-shot 보강
- 자동화: Notion Automation Rule 설계·배포, 버튼(자동 분류 실행) 구성, 리뷰 뷰 운영
- 거버넌스: 임계값(th=0.6) 정책, 재시도·로그 규약, 개인정보·비밀정보 필터 기준
- 대시보드: 칸반/캘린더/갤러리 카드 속성 표준(중요도, 도메인, 상태)

### 서대리(Cursor AI)

- 연동 개발: LLM API 모듈, Notion API 속성 업데이트, 6,000자 본문 추출기
- 품질: JSON 스키마 검증, 용어 일치성 검사, 근거 인용 품질 점수
- 성능·안정성: 배치 처리, 지수 백오프, idem-key, 타임아웃·예외 처리
- 로깅: 입력 토큰, 모델, 응답 시간, 오류 스택 → AI 로그 기록 및 리포팅

## 실행 절차(End-to-End)

1) 수집

- 외부 스크립트가 DB에 페이지 생성(title, 링크) → 상태=초안

2) 트리거(권장)

- 링크 속성 채워진 후 2분 지연 → Automation 시작

3) AI 처리

- 본문 클립(≤6,000자) → v1.1 프롬프트 바인딩 → JSON 결과 수신

4) 매핑

- 목적 요약, 문서 성격, 핵심 기술(도메인), 중요도, 요약, 핵심내용, AI 신뢰도, AI 로그 속성 업데이트

5) 품질·라우팅

- 신뢰도 < 0.6 → 상태=검토요청, "리뷰 대기" 뷰로 이동
- 오류/타임아웃/429 → 상태=AI 처리 실패 (재검토), AI 로그에 원인 기록, 최대 3회 재시도 후 중단

6) 대시보드

- 칸반: 상태 그룹. 카드 필드=문서 제목, 중요도, 핵심 기술(도메인)
- 캘린더: 작성일 캘린더
- 갤러리: 중요도 우선 정렬 노출

## 일정(Phase 1 중심, 2주)

- D+0: 자동화 Rule 초안 배포, 파일럿 5건 드라이런
- D+2: 파일럿 30건 벤치마크(3 도메인×10)
- D+5: 임계값·사전·few-shot 보정, 대시보드 카드 확정
- D+10: v1.1 운영 전환, 리뷰 큐 체계화

---

## 수용기준(AC)

- 매핑 정확도 ≥ 90% (문서 성격, 도메인, 중요도 합산 F1)
- 신뢰도 < 0.6 샘플 중 오검출 비율 ≤ 10%
- 오류 시 상태 전환 및 AI 로그 기록 100% 재현
- 평균 처리 시간 ≤ 8초/건(Automation+LLM 왕복 기준), 95p ≤ 20초
