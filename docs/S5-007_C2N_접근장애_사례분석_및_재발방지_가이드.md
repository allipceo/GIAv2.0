# UI001_C2N 접근장애 사례분석 및 재발방지 가이드

## 1) 요약
- 사건: 기존 C2N 토큰으로 U001 접근 중 전 구간 401 발생 → No6_API 재설치/결속 후 복구(200 OK).
- 핵심 원인: Integration 워크스페이스 설치/활성 불일치 또는 결속 해제.
- 교훈: users/me 401이면 설치/워크스페이스/스코프 우선 점검, 결속(DB/페이지)은 2순위.

## 2) 타임라인
- T0: No5_API로 users/me·DB·pages 모두 401
- T1: DB/페이지 공유 재확인(결속 표기 있음)에도 users/me 401 지속
- T2: 원인 가설 고정(설치/워크스페이스 문제) → 재설치/결속 지시
- T3: No6_API 적용 후 3단계 모두 200 → U001 하단 ‘접근 증빙’ 기록, 카드 메타 갱신 200

## 3) 기술 분석
- 증상: 동일 세션/동일 호스트에서 401, 특히 users/me 401이 선행
- 근본 원인 후보:
  - Integration 워크스페이스 미설치/비활성/불일치
  - DB·페이지 결속 해제(문서 이동·복제 시 흔함)
  - 토큰 로테이션/폐기(보안 정책)
  - 환경변수 미주입·숨은문자

## 4) 복구 SOP(루프 금지 매핑)
- users/me 401 → 설치/워크스페이스/스코프만 점검(토큰 교체 요구 금지)
- users/me 200, DB 401 → DB–Integration 결속만 점검
- DB 200, pages 401 → 페이지–Integration 결속만 점검
- 모두 정상 후 3단계 재검증(users/me → databases/:id → pages/:id)

## 5) 결속 및 설치 체크리스트(선과장 제공)
- Integration: 이름(예: No6_API), 토큰, Installed 스크린샷(워크스페이스 일치), 권한(users/databases/pages:read)
- 리소스: DB ID(📘 ZOBIS 개발문서 DB), 페이지 ID(U001), 두 곳의 ‘연결’ 목록 스크린샷 1장
- 환경: 실행 위치(로컬/서버/CI), 프록시/VPN, 시간 동기화
- 산출물: 3단계 200 원문 1건, U001 ‘접근 증빙’ 링크, 카드 메타 스냅샷 1장

## 6) 자동화 구현 요점(스크립트 정책)
- 환경변수: NOTION_TOKEN, TARGET_DATABASE_ID, U001_PAGE_ID
- 헤더: Authorization Bearer, Notion-Version=2022-06-28, Content-Type
- 스키마 자동 매핑: status/select, rich_text/text/title, date.start, multi_select
- 로그: logs/u001_access_YYYYMMDD.jsonl, 민감정보 마스킹

## 7) 이번 결과
- No6_API로 3단계 200 OK, 증빙 블록/카드 메타 200 OK로 완료
- 원인 추정: 기존 토큰 계열의 설치/결속 불일치

## 8) cURL 템플릿
```bash
# users/me
curl -sS https://api.notion.com/v1/users/me \
  -H "Authorization: Bearer $NOTION_TOKEN" \
  -H "Notion-Version: 2022-06-28"
# DB
curl -sS https://api.notion.com/v1/databases/$TARGET_DATABASE_ID \
  -H "Authorization: Bearer $NOTION_TOKEN" \
  -H "Notion-Version: 2022-06-28"
# 페이지(U001)
curl -sS https://api.notion.com/v1/pages/$U001_PAGE_ID \
  -H "Authorization: Bearer $NOTION_TOKEN" \
  -H "Notion-Version: 2022-06-28"
```
