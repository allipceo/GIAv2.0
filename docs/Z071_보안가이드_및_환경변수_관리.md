# Z071: ZOBIS 보안 가이드 및 환경변수 관리

## 🛡️ 보안 가이드

### 1. 민감한 정보 보호 원칙
```
절대 금지:
├── ❌ API 키를 코드에 하드코딩
├── ❌ 토큰을 Git에 커밋
├── ❌ 민감한 정보를 공개 저장소에 업로드
└── ❌ 환경변수 파일을 Git에 커밋

필수 사항:
├── ✅ 환경변수 사용
├── ✅ .gitignore 설정
├── ✅ 템플릿 파일 제공
└── ✅ 정기적 보안 검토
```

### 2. 환경변수 설정 방법

#### **A) 로컬 개발 환경**
```bash
# 1. config.env 파일 생성
cp config.env.template config.env

# 2. 실제 값 입력
# config.env 파일을 편집하여 실제 API 키 입력

# 3. 환경변수 로드
source config.env  # Linux/Mac
# 또는
# Windows에서는 PowerShell에서 실행
```

#### **B) 서버 배포 환경**
```bash
# Heroku
heroku config:set CSE_API_KEY=your_key
heroku config:set NOTION_TOKEN=your_token

# Google Cloud Run
gcloud run deploy --set-env-vars CSE_API_KEY=your_key,NOTION_TOKEN=your_token
```

### 3. 보안 체크리스트

#### **개발 시 체크리스트**
```
✅ API 키 하드코딩 확인:
├── 코드에서 하드코딩된 키 검색
├── 환경변수 사용 확인
└── .gitignore 설정 확인

✅ 커밋 전 검토:
├── 민감한 정보 포함 여부 확인
├── 환경변수 파일 제외 확인
└── 보안 스크립트 실행
```

#### **배포 시 체크리스트**
```
✅ 환경변수 설정:
├── 모든 API 키 환경변수로 설정
├── 서버 환경변수 확인
└── 테스트 실행으로 검증

✅ 접근 권한 관리:
├── 팀원별 접근 권한 설정
├── API 키 권한 최소화
└── 정기적 권한 검토
```

### 4. 문제 발생 시 대응

#### **A) 민감한 정보 노출 발견 시**
```bash
# 1. 즉시 토큰/키 재발급
# 2. Git 히스토리에서 제거 (git filter-branch)

```

#### **B) 보안 스크립트 실행**
```bash

```

## 🎯 결론

ZOBIS의 보안은 **환경변수 사용**과 **정기적 보안 검토**로 유지됩니다.

**핵심 원칙**: API 키는 절대 코드에 하드코딩하지 않고, 환경변수로 관리하며, .gitignore로 보호합니다.
