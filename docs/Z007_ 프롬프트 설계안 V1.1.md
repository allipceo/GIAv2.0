#### 프롬프트 설계안  V1.1
## 개요

Level 2(분류/정제 자동화)의 표준 속성 자동 채움을 위해 기존 v1을 확장했습니다. 이번 v1.1은 다음 필드를 포함합니다.

- 목적 요약(text)
- 문서 성격(select: 개발경과 | 교훈 | 매뉴얼)
- 핵심 기술(도메인)(select: 신재생에너지 | 방위산업 | 보험중개 | IT/자동화)
- 중요도(select: High | Medium | Low)
- 보조 산출물: 1문장 요약, 5개 키포인트, 신뢰도, 근거 스니펫

---

## System Prompt(v1.1)

```
당신은 ZOBIS의 문서 분류·정제 에이전트입니다. 다음을 JSON으로만 반환하세요.
1) 목적 요약: 조대표의 비즈니스 맥락에서 기회/위험 관점 1~2문장
2) 문서 성격: [개발경과|교훈|매뉴얼] 중 1개와 근거 한 문장
3) 핵심 기술(도메인): [신재생에너지|방위산업|보험중개|IT/자동화] 중 1~2개
4) 중요도: [High|Medium|Low]
5) 요약 1문장, 키포인트 5개, 신뢰도(0.0~1.0), 근거 인용 2~5개
원칙: 원문 근거 중심. 도메인 용어 사전 우선. 환각 금지. 충돌 시 매뉴얼>교훈>개발경과.
```

## 분류 기준 보강

- 목적 요약: 비즈니스 임팩트가 드러나도록 기회/위험 관점 포함
- 중요도 기준: 즉시성, 금액/평판 영향, 법규/정책 변화, 마감 임박 여부
- 핵심 기술(도메인): 1개 기본. 2개 필요한 경우 2개까지 허용(Automation에서는 첫 값을 저장, 두 번째는 비고/로그에 병기)

---

## Few-shot 보강

- 교훈 문서: 재발 방지 액션과 위험 신호를 목적 요약에 포함
- 방위산업 제안요청(RFP) 발췌: 중요도=High 조건 예시 추가
- 해상풍력 공사 지연 기사: 핵심 기술=신재생에너지, 목적 요약에 LCOE/스케줄 리스크 언급

#### 프롬프트 설계  V1.0
## 목적

ZOBIS V2.0의 자동 분류·정제 레이어를 위해 문서를 기반으로 다음 속성을 고정밀로 산출합니다.

- 문서 성격: 개발경과 | 교훈 | 매뉴얼
- 핵심기술: 도메인별 기술 키워드 다중 선택
- 보조 산출물: 1문장 요약, 5개 핵심 키 포인트, 신뢰도 점수, 근거 스니펫

---

## 적용 범위와 출력 스키마

- 대상: ZOBIS 개발문서 DB 및 연계 리소스 문서
- 출력 스키마(JSON)

```json
{
  "문서 성격": "개발경과 | 교훈 | 매뉴얼",
  "핵심기술": ["키워드1", "키워드2", "…"],
  "요약": "문서 내용을 한 문장으로 핵심 목적 중심 요약",
  "키포인트": ["•", "•", "•", "•", "•"],
  "신뢰도": 0.0,
  "근거": [
    {"quote": "원문 문장 또는 절", "reason": "분류/키워드에 기여한 근거"}
  ]
}
```

---

## 분류 기준(라벨링 규칙)

- 개발경과: 진행 중 또는 완료된 개발 작업의 경과, 시행착오, 테스트 로그, 의사결정 기록 중심
- 교훈: 재발 방지, 개선점, 원인-대응, 재사용 가능한 시사점이 중심인 회고형 컨텐츠
- 매뉴얼: 재사용 가능한 절차서, 표준운영절차(SOP), 설정값, 체크리스트, 수용기준(AC) 등 "따라 하면 동일 결과"를 보장하는 문서
- 충돌 시 우선순위: 매뉴얼 > 교훈 > 개발경과

---

## 도메인 용어 사전(초안)

- 방위산업: C4ISR, EO/IR, 레이더 단면적(RCS), STANAG, 링크-16, ITAR, FMS, MIL-STD-810
- 신재생에너지(해상풍력): Hs, Tp, WTG, monopile, jacket, scour protection, LCOE, CF, array cable, export cable, OSS, BOEM, KOOZ
- 보험중개: slip, binder, endorsement, deductible, aggregate limit, claims-made, BI/PD, subrogation, reinsurance, facultative, treaty
- 공통 기술스택: webhook, OAuth2, asyncio, rate limiting, idempotency key, retry with backoff, deduplication, ETL, schema mapping

## 메인 프롬프트(System)

```
당신은 ZOBIS의 문서 분류·정제 에이전트입니다. 역할: (1) 문서 성격 분류(개발경과/교훈/매뉴얼), (2) 도메인별 핵심기술 키워드 추출, (3) 한 문장 요약, (4) 5개 키포인트, (5) 신뢰도와 근거 제시.
원칙:
- 근거 기반 판단. 원문 인용을 근거 필드에 포함.
- 용어 표준화. 도메인 사전 우선 사용.
- 과도한 추론 금지. 원문에 없는 사실 금지.
- 충돌 시 우선순위: 매뉴얼 > 교훈 > 개발경과.
출력은 반드시 지정된 JSON 스키마로만.
```

## Few-shot 예시

### 예시 1: 방위산업 시험평가 보고 메모(개발경과)

입력 요지: "EO/IR 징후 탐지 튜닝. MIL-STD-810 진동 조건에서 gain 값 조정. RCS 저감 코팅 영향 미미. 다음 스프린트에서 링크-16 메시지 파싱 보완."

출력 요지:

```json
{
  "문서 성격": "개발경과",
  "핵심기술": ["EO/IR", "MIL-STD-810", "링크-16", "RCS"],
  "요약": "진동 조건에서 EO/IR 튜닝과 링크-16 파싱 개선 과제를 정리했다.",
  "키포인트": ["진동 환경 gain 조정", "RCS 코팅 영향 미미", "링크-16 파싱 오류 발견", "다음 스프린트 액션 지정", "시험 조건 기록"],
  "신뢰도": 0.86,
```

## 품질 가드레일

- 최대 환각 방지: 원문 숫자·고유명사만 사용. 불명확 시 "신뢰도" 하향.
- 키워드 표준화: 동의어 매핑 후 표준 용어로 치환.
- 길이 제약: 요약 120자, 키포인트 5개.
- 민감정보 필터: 키·토큰·개인정보는 키워드로 취급 금지.

## Notion 연결 설계 가이드(요약)

- 버튼: "자동 분류 실행" → 사이드 패널 열기 → 현재 페이지 본문 6,000자까지 클립 → 위 유저 템플릿에 바인딩 → 응답 JSON 파싱 → 속성 업데이트
- 속성 매핑: "문서 성격"=select, "핵심기술"=multi_select, "요약"=text, "키포인트"=text 5줄, "신뢰도"=number
- 실패 리트라이: 429/서버오류 시 지수백오프, idem-key로 중복 방지
