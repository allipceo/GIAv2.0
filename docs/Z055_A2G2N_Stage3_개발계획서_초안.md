### **🔧 Stage 3 상세 구현 계획**

#### **3.1 텍스트 추출기 (Text Extractor)**

**목적**: Notion 페이지에서 텍스트 콘텐츠 추출 및 전처리

**기능**:
- Notion API를 통한 페이지 콘텐츠 추출
- 마크다운/HTML 파싱 및 텍스트 정제
- 메타데이터 추출 (제목, 작성일, 태그 등)
- 텍스트 전처리 (불용어 제거, 토큰화)

**구현 파일**: `src/stage3_text_extractor.py`

**주요 메서드**:
```python
class TextExtractor:
    def extract_page_content(self, page_id: str) -> dict
    def preprocess_text(self, raw_text: str) -> str
    def extract_metadata(self, page_data: dict) -> dict
    def validate_content(self, content: dict) -> bool
```

#### **3.2 AI 분석 엔진 (AI Analysis Engine)**

**목적**: 추출된 텍스트를 AI로 분석하여 인사이트 도출

**기능**:
- 키워드 추출 및 중요도 분석
- 주제 분류 및 카테고리 매핑
- 감정 분석 및 톤 분석
- 요약 생성 및 핵심 포인트 추출

**구현 파일**: `src/stage3_ai_analyzer.py`

**주요 메서드**:
```python
class AIAnalyzer:

    def analyze_sentiment(self, text: str) -> dict
    def generate_summary(self, text: str) -> str
```

**Step 3: AI 분석**
- 키워드 추출 및 중요도 분석
- 주제 분류 및 카테고리 매핑
- 감정 분석 및 요약 생성

**Step 4: 분류 및 우선순위**

**Step 5: 후속 액션**

아래는 서대리 초안(Z055 요지)와 기존 Z059 계획을 통합·정밀화한 Stage 3 최종 계획(오류 재발 방지 강화판)입니다. Stage 2에서 반복된 오류 유형을 기준으로 게이트와 체크리스트를 촘촘히 넣었습니다.

### 0. 목표와 합격 기준

- 기능 목표: 자동 분석 성공률 ≥ 95%, 분류 정확도 ≥ 90%, 액션 성공률 ≥ 95%
- 성능 목표: 평균 처리시간 ≤ 3분/건
- 안정성 목표: 가용성 ≥ 99.5%, 치명 오류 0, 롤백 ≤ 5분
- 합격 게이트: G0(스키마·키), G1(단건), G2(10건), G3(주기 배치)

### 1. 아키텍처(최종)

- 트리거: Notion 페이지 생성 이벤트 → 워커 큐
- 파이프라인: extract → prompt(v1.2) → map(Z041) → branch(Z042) → actions
- 저장/관측: 페이지 속성 업데이트 + 실행 로그(Z046) + 매핑(Z047) + 리포트(Z051)
- 모니터링: 검토 큐, 고우선 인사이트, 실패 로그 뷰 + 경보 기준(성공률<90% 또는 5xx 3회)

### 2. 오류 재발 방지(스테이지2 교훈 반영)

- 스키마 잠금
    - “최소 6개 속성” 계약서 고정: 문서 제목(title)·링크(url)·Google Drive URL(url)·수집 경로(select=AI2G)·작성일(date.start)·상태(status=초안)
    - 배포 전 “화면→JSON” 1:1 대조 캡처 의무(속성명·옵션 철자)
- 페이로드 계약 검증
    - 사전 스키마 GET 검증 통과 후에만 POST 실행
    - 전송 JSON과 응답 전문을 실패 시 반드시 보존
- 키/권한 게이트
    - /v1/users/me 200, 대상 DB 권한 연결 검증을 G0 게이트로 강제
- 실행 환경 고정
    - 웹훅 /health 200(로컬·외부) 캡처 의무
    - FLASK_SKIP_DOTENV=1 또는 FastAPI 전환 가이드 상시 유지
- 롤백·격리
    - 실패 시 즉시 시뮬레이션 큐(jsonl)로 격리/재플레이
    - 기능 플래그로 Action(알림/태스크) 비활성화 후 단일 단계 재시도 허용

### 3. 단계별 게이트·체크리스트

- G0(사전 점검)
    - 스키마 캡처 2장(속성·옵션) 확인
    - me 200, DB 권한 OK
    - /health 200(로컬·외부), 기동 로그 10줄 보관
- G1(단건)
    - “최소 6개”로 단건 생성 → page_id 확보
    - 상태=초안, 6개 속성 채움 검증
    - Z046·Z047 업데이트
- G2(10건)
    - 동일 페이로드 패턴으로 10건 배치
    - 성공률·평균 처리시간·분기 분포 보고
    - 실패 시 전송 JSON+응답 전문 제출
- G3(주기 배치)
    - KPI 안정 2회 연속 충족 시 시간/이벤트 트리거 전환
    - 경보 룰 적용·운영 대시보드 상시 감시

### 4. 파이프라인 세부 절차(실행)

1) 텍스트 추출

- meta.json 요약 → 본문 → PDF+OCR 보조, EMPTY_TEXT 라벨링

2) 프롬프트 v1.2

- 입력: 목적·주제 힌트, 본문, meta.json
- 타임아웃 60s, 재시도 1

3) 매핑(Z041)

- 목적요약·핵심5·근거·중요도·신뢰도·제안액션·리소스타입·링크/Drive·작성일
- 범위·형식 검증, 누락 MAP_MISSING_FIELD

4) 분기(Z042)

- 신뢰도<60 또는 근거 없음 → 검토요청
- 중요도≥80 → 액션 후보
- 중요도≥90 & 신뢰도≥70 → 즉시 알림

5) 액션

- Slack 보고, 태스크 생성
- 실패 시 5/15/45s 재시도 → 실패 큐 → 경보

### 5. 관측·품질 지표

- 로그 필드: trace_id, step, status, duration_ms, err_code, err_msg
- KPI: 자동 분석 성공률, 분기 정확도, 액션 성공률, 평균 처리시간
- 알림: 성공률<90% 또는 5xx 3회 연속

### 6. 보안·키 관리

- 키는 비밀저장소/환경변수. 레포·로그 평문 금지
- 외부 호출 TLS, 필요 시 서명 검증 토글

### 7. 롤아웃(업데이트)

- D0: G0 통과(스키마/키/헬스 증빙), 단건 분석 리포트
- D0+1: 10건 배치 분석 및 KPI 보고, 액션 플래그 단계적 온
- D0+3: 주기 배치 전환, 대시보드 상시 모니터링

### 8. R&R

- 선과장: 품질·게이트 운영 총괄, KPI 보고, 롤백 승인
- 서대리: 실행·로그·증빙·실패 리포트
- 나실장: 운영 승인, 리스크·자원 우선순위

### 9. 실패 시 즉시 대응 룰

- 400(validation): 화면→JSON 대조, 최소 6개로 축소 재시도
- 401/403: 키 회전·권한 연결 즉시 점검
- 타임아웃: 60→90s 일시 상향 후 원인 분석
- 연속 실패: 시뮬레이션 큐 전환·재플레이
