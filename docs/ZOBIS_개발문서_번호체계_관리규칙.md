# ZOBIS 개발문서 번호체계 관리규칙

**작성자**: 서대리 (Cursor AI)  
**작성일**: 2025년 1월 17일  
**목적**: ZOBIS 프로젝트 개발 진행 상황 체계적 관리

## 📋 번호체계 규칙

### 기본 형식
```
Z[번호]_[프로젝트명]_[작업내용]_[단계]_[상태]
```

### 번호 할당 규칙
- **Z001**: ZOBIS 문서동기화 작업 1단계 (완료)
- **Z002**: 다음 개발 작업 (예: AI 분석 시스템 구축)
- **Z003**: 그 다음 개발 작업 (예: 실시간 모니터링 대시보드)
- **Z004**: 계속 순차적으로 증가

### 문서명 예시
```
Z001_ZOBIS_문서동기화_작업_1단계_개발완료보고서.md
Z002_ZOBIS_AI분석시스템_구축_2단계_개발완료보고서.md
Z003_ZOBIS_모니터링대시보드_구축_3단계_개발완료보고서.md
```

## 📁 저장 위치

### 개발 완료 보고서
- **위치**: `docs/` 폴더
- **형식**: `Z[번호]_[프로젝트명]_[작업내용]_[단계]_[상태].md`

### 개발 중간 보고서
- **위치**: `docs/` 폴더 또는 프로젝트 루트
- **형식**: `Z[번호]_[프로젝트명]_[작업내용]_[단계]_진행보고서.md`

## 🔄 관리 프로세스

### 1. 새 개발 작업 시작 시
1. 이전 번호 확인
2. 다음 번호 할당 (Z001 → Z002 → Z003...)
3. 문서명 규칙에 따라 생성
4. `docs/` 폴더에 저장

### 2. 개발 완료 시
1. 완료 보고서 작성
2. 교훈(Lessons Learned) 포함
3. 다음 단계 제안 포함
4. 번호 체계에 따라 저장

### 3. 중간 보고 시
1. 진행 상황 업데이트
2. 문제점 및 해결방안 기록
3. 예상 완료 시점 명시
