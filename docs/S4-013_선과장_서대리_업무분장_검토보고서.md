## ❓ **서대리 질문사항**

### **1. G1 검증 범위 명확화**
**질문**: G1 검증에서 "C2N-Health(dryrun), C2N1(dryrun), C2N2(apply 1건), C2N3(apply 1건)"라고 하셨는데, 각각의 구체적인 테스트 시나리오가 있나요?

**예상 답변**: 
- C2N-Health: 시스템 상태 점검 (권한, 스키마, 연결 상태)
- C2N1: 개발지시문 읽기 테스트
- C2N2: 개발결과 저장 테스트 (실제 페이지에 "### 개발결과" 섹션 생성)
- C2N3: 뉴스클리핑 자료 등록 테스트 (Z072에 결과 링크 추가)

### **2. KPI 수집기 구현 범위**
**질문**: KPI 수집기에서 "success_rate, p95_latency_ms, dedup_skip_rate, failures_7d_by_cause" 메트릭을 수집하는데, 이 데이터를 어디서 수집하고 어떤 형태로 저장해야 하나요?

**예상 답변**:
- **수집 위치**: webhook_server.py의 각 라우트에서 실행 시간, 성공/실패 상태 수집
- **저장 형태**: JSON 파일 + 요약 md 파일
- **저장 위치**: logs/kpi/ 디렉토리
- **대문 연동**: Notion API를 통해 KPI 카드에 실시간 반영

### **3. G2 배치 파일럿 데이터**
**질문**: G2 소규모 배치 파일럿 10건을 실행할 때, 어떤 종류의 데이터로 테스트해야 하나요? 실제 뉴스클리핑 데이터인가요, 아니면 테스트용 더미 데이터인가요?

**예상 답변**:
- **테스트 데이터**: 실제 뉴스클리핑 URL 10건
- **테스트 범위**: C2N3 프로세스 (URL → 중복검사 → DB 등록 → Z072 링크 추가)
- **성공 기준**: 10/10 성공, 평균 처리 시간 5분 이내

### **4. 번호체계 프로토타입 구현 방식**
**질문**: "최대값+1 원자적 예약 → 충돌 시 다음 번호 스킵 → 이력 기록" 구현에서, 이 번호체계는 어떤 DB의 어떤 필드에 적용되나요?

**예상 답변**:
- **적용 대상**: ZOBIS개발문서DB의 문서 번호 필드
- **패턴**: ZNNN_ (예: Z080, Z081, Z082...)
- **구현 방식**: Notion API를 통해 최대값 조회 → 원자적 증가 → 충돌 시 스킵
- **이력 기록**: 충돌 발생 시 로그에 기록

### **5. 문서 업데이트 범위**
**질문**: Z075와 Z077 문서 업데이트에서 "실행키(HMAC+nonce+ts)·자동 주입 정책·실패 대처표"와 "최소 입력 표·실패 대처표"를 추가한다고 하셨는데, 이 문서들이 ZOBIS개발문서DB에 있다면 서대리가 직접 수정할 수 있나요?

**예상 답변**:
- **Z075, Z077**: ZOBIS개발문서DB에 있는 문서
- **수정 권한**: 서대리는 Notion API를 통해 수정 가능
- **수정 방식**: 기존 문서에 섹션 추가 또는 새 버전 생성
- **검토**: 선과장님이 최종 검토 후 승인

   - 개발지시문 읽기 테스트
   - 데이터 추출 정확성 확인

3. **C2N2 apply 1건 테스트**
   - 실제 개발결과 저장
   - "### 개발결과" 섹션 생성 확인
   - 스크린샷 촬영

4. **C2N3 apply 1건 테스트**
   - 뉴스클리핑 자료 등록
   - Z072 "케이스 3 결과 링크" 추가 확인
   - 스크린샷 촬영

### **Phase 2: KPI 수집기 구현 (Week 1)**
1. **메트릭 수집 로직 구현**

2. **데이터 저장 시스템**
   - JSON + 요약 md 형태로 저장
   - 대문 KPI 카드 연동 준비

### **Phase 3: G2 배치 파일럿 (Week 2)**
1. **10건 테스트 데이터 준비**

2. **배치 실행 및 모니터링**
   - 동시성 3~5, 재시도 1회 설정
   - 성공률 100% 목표 달성

### **Phase 4: 번호체계 프로토타입 (Week 3)**
1. **ZNNN_ 자동 생성 로직**
   - 최대값+1 원자적 예약 구현

2. **회귀 테스트**
   - 최근 20건 ZNNN_ 패턴 검증
   - 경합 상황 테스트

### **Phase 5: 문서 업데이트 (Week 4)**
