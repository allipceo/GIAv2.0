## ❓ **서대리 질문사항**

### **1. C2N-Health와 C2N1의 관계**
**질문**: C2N-Health는 시스템 상태 점검용이고, C2N1은 지시서 읽기용인데, 두 버튼을 모두 실행해야 하나요? 아니면 C2N-Health는 선택사항인가요?

**서대리 이해**:
- C2N-Health: 시스템 전반 상태 점검 (권한, 스키마, 연결)
- C2N1: 특정 지시서 읽기 및 상태 확인
- **실행 순서**: C2N-Health → C2N1 (시스템 점검 후 지시서 읽기)

### **2. "대상(Z062 등) 지시서 조회"의 구체적 의미**
**질문**: "대상(Z062 등) 지시서 조회"에서 Z062는 예시인가요? 실제로는 어떤 지시서를 읽어야 하나요?

**서대리 이해**:
- Z062는 예시 문서 번호
- **실제 대상**: 선과장님이 지정하는 구체적인 지시서 페이지
- **확인 방법**: PAGE_ID 자동 탐지 또는 수동 지정

### **3. "읽음 표시 또는 상태 점검 로그 생성"의 구현**
**질문**: C2N1 실행 후 "읽음 표시"는 Notion 페이지에 어떤 형태로 기록되나요? 별도 필드에 기록하나요?

**서대리 이해**:
- **읽음 표시**: 페이지 속성에 "마지막 읽은 시간" 필드 업데이트
- **상태 점검 로그**: 별도 로그 파일에 상세 정보 기록
- **구현 방식**: Notion API를 통한 페이지 속성 업데이트

### **4. "### 개발결과" 섹션 자동 생성**
**질문**: C2N2에서 "앵커 미존재 시 섹션 자동 생성"할 때, 어떤 위치에 생성하나요? 페이지 맨 아래인가요?

**서대리 이해**:
- **생성 위치**: 페이지 맨 아래에 "### 개발결과" 헤딩 생성
- **내용**: 3줄 요약 + 근거 링크 블록 추가
- **중복 방지**: 기존 섹션이 있으면 그 하단에 추가

### **5. Z072 결과 링크 자동 반영**
**질문**: C2N2 실행 후 Z072에 결과 링크가 자동 반영되는데, 이는 어떤 형태로 추가되나요?

**서대리 이해**:
- **추가 위치**: Z072 하단 "케이스 2 결과 링크" 섹션
- **링크 형태**: "개발결과 업데이트 — YYYY-MM-DD HH:mm KST" + 페이지 링크
- **자동화**: C2N2 실행 완료 시 자동으로 Z072에 추가

## 🚀 **서대리 실행 계획**

### **Phase 1: C2N-Health 실행 (즉시)**
1. **시스템 상태 점검**
   - users/me, databases 200 OK 확인
   - schema_hash 경고만 기록 확인
   - 권한, 스키마, 연결 상태 종합 점검

2. **로그 생성**
   - logs/c2n1_health_<ts>.md 파일 생성
   - 시스템 상태 요약 3줄 작성

### **Phase 2: C2N1 실행 (Health 완료 후)**
1. **지시서 읽기**
   - 대상 지시서 페이지 조회
   - 내용 분석 및 상태 확인
   - 읽음 표시 업데이트

2. **제출물 생성**
   - logs/c2n1_dryrun_<ts>.md 파일 생성
   - 요약 3줄: 확인 대상, 상태 요약, 이슈 유무
   - Z072 링크 첨부 (필요시)

### **Phase 3: C2N2 실행 (C2N1 완료 후)**
1. **개발결과 기록**
   - "### 개발결과" 섹션 확인/생성
   - 3줄 요약 + 근거 링크 추가
   - 중복 방지 가드 준수

2. **제출물 생성**
   - "개발결과 업데이트 — YYYY-MM-DD HH:mm KST" 블록 생성
   - 근거 링크 ≥ 1개 추가
   - 실행 로그 생성
   - Z072 결과 링크 자동 반영 확인

## 📋 **운영 유의사항 준수**

### **1. 자동 주입 정책**
- **PAGE_ID·DEV_DB_ID**: 런타임 자동 탐지
- **미탐지 시**: 안전 차단과 안내 로그 출력
- **구현**: webhook_server.py에서 컨텍스트 자동 탐지

### **2. 가드 상시 ON**
- **HMAC 서명**: X-Signature 헤더 검증
- **ts·nonce**: 타임스탬프 및 중복 방지
- **JSON Schema**: 입력 데이터 검증
- **schema_hash**: 드라이런=경고, 적용=차단

### **3. 추적 일원화**
- **결과 링크**: Z072 하단에서 집계 확인
- **실행 요약**: 모든 실행 결과를 Z072에 통합
- **모니터링**: 실시간 상태 확인 가능
