Z072_서대리-선과장 작업경과 및 결과 공유 시스템
### 목적

서대리(로컬)와 선과장(Notion)이 📘 ZOBIS 개발문서 DB를 공동 사용하며 작업 경과·결과를 안전하게 공유하기 위한 표준 절차와 스크립트를 제공합니다.

---

### 1) 접근·권한 준비

- DB 공유: 📘 ZOBIS 개발문서 DB → Share → Connections → 서대리 통합 Can edit 초대 [📘 ZOBIS 개발문서 DB](https://www.notion.so/ZOBIS-DB-30ac67d267054befb914a77ce9443ce3?pvs=21)
- 토큰: ntn_… 내부 통합 토큰을 세션/시크릿에만 보관(채팅 금지)
- API 버전: Notion-Version=2022-06-28, UTF-8 고정

---

### 2) 헬스체크(필수)

- users/me=200 → 토큰 유효
- databases/{id}=200 → DB 접근 OK
- 오류 판독: 401 토큰/주입, 403 미공유, 404 ID 오타

---

### 3) 동기화 정책

- 로컬→Notion 단방향 기본. 제목 중복 방지는 Z번호 접두(ZNNN_) + page_id 캐시로 처리
- 실패는 상태=“AI 처리 실패 (재검토)”로 표준화
- 번호 체계: 생성 직전 원자적 +1 예약, 충돌 시 다음 번호 스킵 후 이력 기록

---

### 4) 가드(항상 켜두기)

- 요청 직전 불변 검증: parent.database_id, page_id 소속, schema_hash 일치
- 타입 밸리데이션: [status.name](http://status.name), date.start, url 등
- 로그 표준: 요청 전문, props.keys, 응답 본문, page_id, 상태명

---

```python
NOTION_API = "https://api.notion.com/v1"
HEADERS = lambda t:{"Authorization":f"Bearer {t}","Notion-Version":"2022-06-28","Content-Type":"application/json; charset=utf-8"}

```

- scripts/notion_[probe.py](http://probe.py) (토큰·DB·schema_hash)

```python
n = NotionClient(TOKEN); n.users_me(); n.get_database(DB_ID); open('.schema_hash.txt','w').write(build_schema_hash(...))
```

- scripts/list_[pages.py](http://pages.py) (페이지네이션)

```python
for it in iter_db(DB_ID, page_size=50, sorts=[{"timestamp":"last_edited_time","direction":"descending"}]): print(title, id)
```

```python
page = n.get_page(PAGE_ID); blocks = n.list_block_children(PAGE_ID)
```

- scripts/find_[z062.py](http://z062.py) (테스트 페이지 탐색)

```python
payload={"filter":{"property":"문서 제목","title":{"contains":"Z062"}}}; res=n.query_database(DB_ID,payload)
```

### 2. 핵심 기능 요구 사항 (FR)

### 2.1 파이프라인 안정화

- status 갱신: branch 단계 상태(status) property_id 기반
- 소속 검증: parent.database_id 강제 및 page_id 소속 확인
- 요청 전 가드: 요청 직전 불변 검증 미들웨어 상시 적용

### 2.2 배치 실행(G2)

- 동시성 3~5, 실패 자동 재시도 1회, 잔여 실패는 "AI 처리 실패 (재검토)"

### 2.3 번호 체계 자동 부여(ZNNN_)

- 생성 직전 최대값 +1 원자적 예약, 충돌 시 다음 번호 스킵 및 이력 기록
- 재시도·롤백 규칙 포함

### 2.4 실행버튼 및 대시보드

- 대문 상단: 상태 점검, 캐시 새로고침 2종 버튼 배치
- 모니터 카드: 최근 실패, 검토대기, 최근 7일 변경 집계 뷰

### 3. 시행착오 회피 전략(교훈 내재화)

- 인코딩: PowerShell 7+ 또는 UTF-8 고정(chcp 65001, In/OutEncoding), ConvertTo-Json → UTF-8 바이트 전송
- property_id: Databases GET 원문만 사용(파생·정규화 금지). 캐시는 id·type만 보관
- 캐시 일관성: schema_hash 포함. 불일치 시 배치 금지 및 캐시 재생성
- parent 누락: pages POST/PATCH 모두 parent.database_id 또는 대상 page의 DB 소속 확인 가드
- 키 불변: build_props 단일 진입점에서 property_id만 사용, 이후 단계는 값만 추가
- 타입 스키마: [status.name](http://status.name), date.start, url 등 전송 직전 타입 밸리데이션
